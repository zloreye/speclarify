name: feature-code
description: 在功能文档、技术方案和任务规划确认后，实现并验证功能任务。
---

读取 `specs/features/{功能名}/功能文档.md`、`specs/features/{功能名}/技术方案.md`、`specs/features/{功能名}/任务规划.md` 和当前任务相关代码。

用户指定范围时按该范围执行；未指定时，执行下一个依赖已满足的未完成任务。

根据任务性质判断是否使用 TDD（测试驱动开发）。无论采用哪种开发方式，每个任务完成前都必须执行与任务验证标准及相关 AC 相匹配的充分验证。涉及 UI（用户界面）时，优先使用 Playwright MCP（让 AI 操作浏览器验证页面行为的服务）自行验证；无法可靠验证的部分再请用户验收。

发现会影响功能行为或改变既有决策的问题时，通过 `clarify` 达成共同理解；不改变既有决策的实现细节由 AI 自行处理。决策发生变化时，同步更新对应文档。

任务完成后，将任务规划中对应任务的 `- [ ]` 更新为 `- [x]`，并持续更新 `specs/features/{功能名}/开发报告.md`，记录实现范围、对应 AC、验证方式、验证结果以及待用户验收的内容。存在未完成的必要验收时，任务保持未完成状态。

所有任务完成后，对全部 AC 进行功能整体验证；全部通过后，才在开发报告中标记功能完成，并将 `specs/开发路线图.md` 中对应任务的 `- [ ]` 更新为 `- [x]`。
